Hand off the roles, not the tasks.

An agent in ADI isn't a chat window. It's a definition you keep: a model, a prompt, the exact tools it may run, the secrets it may use, and a memory of its own.

You don't build any of that by hand, and you don't learn the platform to get it. ADI comes with an agent whose job is ADI: you ask, and it writes the tool, files the project, puts the service up.

# agents/support-agent/agent.yaml — the whole of it
name:     support-agent
backend:  claude-sdk
model:    opus
prompt:   ./prompt.md

  - refund-lookup   # it wrote this one itself, the second time it needed it

It makes its own tools

The second time an agent needs the same thing, it writes itself a CLI for it — or you ask for one. Each gets the tools you ticked, not the ones you didn't.

It doesn't stop when you close the tab

Triggers fire on events. Tasks outlive the run that made them.

Then close the laptop.

The same store runs headless on a Linux box, and keeps running after you log out. No open port, no ssh — it dials out to pair.

Then it doesn't need you. A service stays up; a webhook or an event starts an agent with the prompt you wrote for exactly that alert. What it works out is in the task tree when you get back.

Every machine you pair reaches the others, authorised by key, exposing only the ports you named. Your iPhone too — any dashboard, on any of them. That app is in review and not downloadable yet.

One store. One control panel.

Everything ADI runs lives in one directory, browsable and editable at app.adi on your own machine — a name your own DNS answers, which installs as an app if you'd rather it were one.

Part of your machine, not a tab in someone's cloud.

There is no account to create. Your projects, your database, your secrets and your agents' memory sit in one directory on your own disk, under your own backups. Pull the network and the store is still yours.

You bring your own model account — that call goes to whichever provider you already pay for. A few other things reach the network, and they're named right here. None of them reports you: there is no telemetry or product-analytics SDK anywhere in the source.

  • Your model provider — inference goes to the account you already pay for.
  • The update check — one static file from GitHub Releases, at login and every six hours. adi-mono update disable stops it.
  • The mesh relay, if you pair two machines over the internet — iroh's public relays by default; name your own in mesh.toml.
  • Signing in with Google or GitHub — a router we run trades the sign-in for your token and hands it into your own secrets store. No database, no session, no ADI account.
  • The embedding model — the weights download once, from Hugging Face, then run here.

What it isn't.

ADI is early. It's built and used every day by one person, and that person wrote it. There are no logos on this page and no case studies, because there is nothing yet that would be true.

It doesn't ship your product while you sleep. There's no seat count, no licence key, and nothing that asks permission to run on hardware you own.

Free for you. Licensed past $1M or ten people.

ADI is free for you. Using it for yourself — your own projects, learning, anything that isn't commercial — is free for anyone. Using it for a business is free too, as long as that business is under $1M a year and under ten people.
