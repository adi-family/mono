## Where it is implemented

One token file, loaded everywhere as plain CSS. Change a value in `design/tokens.css` and every
surface below follows.

| Surface | How it draws the system |
| --- | --- |
| [`crates/adi-css`](../crates/adi-css) | The `adi-*` classes the control panel is written against. `_tokens.scss` `@use`s the token file; `_components.scss` is the shell, tables, forms, buttons and chips of §6. Compiled by Trunk for the webapp and by `grass` into `adi_css::STYLESHEET` for pages rendered by Rust. |
| [`crates/adi-ui`](../crates/adi-ui) | The component library: Tailwind utilities mapped onto the tokens (`styles/ui.css`), the components, the flat monochrome `Mark`, and the icon set — `Icon` / `Lucide`, generated by `build.rs` from `icons/*.svg`. Also the self-hosted faces: Geist, Geist Mono and Bricolage Grotesque under `fonts/`. |
| [`crates/adi-webapp`](../crates/adi-webapp) | The control panel at `app.adi`. Dark, no theme toggle; one SCSS partial per page under `styles/pages/`. |
| [`crates/adi-mesh-client`](../crates/adi-mesh-client) | The fleet client at `mono-mesh-client.withadi.dev`. Links the token file and the font sheet directly. |
| [`crates/adi-hive/src/notfound.rs`](../crates/adi-hive/src/notfound.rs) | The front door's `404`, the mesh page, and the page shell the proxy's errors and the mesh gateway's pages are drawn into. The token file is inlined at compile time. |
| [`crates/adi-webapp-api/templates/dashboard`](../crates/adi-webapp-api/templates/dashboard) | The shell every user dashboard is generated into. Self-contained; the token file is spliced in at build time (`handlers/dashboards.rs`). |
| A dashboard's own `frontend/modules/*.ts` | The panels an agent writes. They inherit the shell's tokens and are held to the same rules — but **migration never reads them**, so the shell can be re-generated with a new palette while a panel goes on naming tokens that no longer exist. The scaffold README states the contract; §*What this replaced* below is what happens when it is not read. |
| [`apps/macos`](../apps/macos), [`apps/ios`](../apps/ios) | The menubar app and the fleet app: the palette as Swift constants, Lucide as vector assets, the mark from `Trefoil.swift`. |
| [`apps/macos/dmg`](../apps/macos/dmg) | The disk image background, rendered from `background.html` with the tokens pasted in. |
| The landing, `adi-family/withadi.dev` | An Astro site with its own copy of the token file and the fonts, in the `.light` set. |

Two scripts keep the assets pinned and refetchable:

- [`scripts/fonts.sh`](../scripts/fonts.sh) — the three faces from Google Fonts, per-script woff2 subsets, and the `@font-face` sheet.
- [`scripts/lucide.sh`](../scripts/lucide.sh) — the icon set at one `lucide-static` release; `add <name>` to grow it.

## What this replaced

The first thing the swap broke was a dashboard: `adi-launch.adi` kept `--muted`, `--online`,
`--down` and `--panel` in its panels for a day after the shell around them had moved to the new
palette. An undefined custom property inherits rather than failing, so every label and meta line
rendered at full ink and the board read as uniformly loud — the exact failure §1 names — with
nothing in the markup to say why. Anything that draws with the tokens but is not migrated with
them can go the same way; that is the row added to the table above.

Until 2026-09-02 this file described a different language — glass on chrome, raised cards, a
lit mark with a gradient across each lobe, two generated OKLCH palettes kept in step by hand,
IBM Plex and JetBrains Mono. `design/DESIGN.md` §1 says why it went: uniform loudness and
decoration without a rule. The disk image was the first surface built to the old language and
the last to leave it; `apps/macos/README.md` still documents the Finder mechanics, which did not
change.
